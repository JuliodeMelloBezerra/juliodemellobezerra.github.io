Miller–Rabin · Arnault's Method · Adversarial Primality

Constructing Strong Pseudoprimes

How to forge composite numbers n = p1p2p3 that fool deterministic Miller–Rabin tests across every prime base b ≤ t; and how modulo-4 CRT alignment, segmented sieving, and quadratic reciprocity make the search orders of magnitude faster.

By Julio de Mello Bezerra

01 · The Miller–Rabin Primality TestWhen primality testing trusts a fixed basis

This SageMath (Python) program efficiently constructs strong pseudoprimes, which intuitively are composite numbers that pass badly-implemented primality tests. It was inspired by a Capture-The-Flag (CTF) challenge that required tricking a server into using a composite number instead of a prime in its Diffie–Hellman encryption scheme.

While the main idea follows the method described by Arnault[1], we develop an implementation and specific techniques that make the program much more efficient: a single-pass modulo-4 CRT alignment, a specialized segmented sieve, custom optimized primality tests, and an asymptotic analysis of optimal parameters. Our goal is to construct strong pseudoprimes with respect to the base consisting of all primes smaller than a given \(t > 0\).

Any prime number \(p\) satisfies two fundamental algebraic conditions:

  • Fermat's little theorem: for any base \(a \in \mathbb{Z}\) not divisible by \(p\), we have \(a^{p-1} \equiv 1 \pmod p\).
  • Roots of unity over \(\mathbb{F}_p\): the only square roots of unity modulo \(p\) are \(\pm 1\), that is, \(x^2 \equiv 1 \pmod p \iff x \equiv \pm 1 \pmod p\).

The idea behind the Miller–Rabin probabilistic primality test is to check, for a given odd \(n \in \mathbb{Z}\) and coprime base \(a \in \mathbb{Z}\), whether \(n\) satisfies the two properties above. Write \(n - 1 = 2^s d\) with \(d\) odd. If \(n\) were prime, Fermat's little theorem would give \((a^d)^{2^s} \equiv 1 \pmod n\), and taking \(s\) successive square roots forces every intermediate value before the first \(+1\) to be congruent to \(-1\). Thus it is enough to check whether:

$$a^d \equiv 1 \pmod n \quad \text{or} \quad (a^d)^{2^r} \equiv -1 \pmod n \quad \text{for some } 0 \le r \le s - 1.$$

If this holds for a composite \(n\), we call \(n\) a strong pseudoprime to the base \(a\). No composite number is a strong pseudoprime for all bases: at most \(1/4\) of the bases \(1 < a < n - 1\) can make \(n\) pass the test, so \(k\) random bases fail to detect a composite with probability at most \((1/4)^k\). However, if the bases are chosen from a fixed set — such as the set \(T\) of all primes smaller than \(t > 0\) — then it is possible to construct a composite number that is a strong pseudoprime to all bases in \(T\) simultaneously[1][2].

02 · Arnault's MethodFrom Carmichael numbers to strong pseudoprimes

To understand Arnault's method[1] (and its presentation in the Appendix of Prime and Prejudice[2]), recall that an odd composite integer \(n\) is a Carmichael number if it passes Fermat's primality test \(a^{n-1} \equiv 1 \pmod n\) for every base \(a\) coprime to \(n\). By Korselt's criterion, a square-free odd composite \(n = p_1 p_2 \cdots p_h\) is a Carmichael number if and only if:

$$(p_i - 1) \mid (n - 1) \quad \text{for all } i \in \{1, \dots, h\}.$$

Why isn't every Carmichael number automatically a strong pseudoprime? Write \(n - 1 = 2^S D\) and \(p_i - 1 = 2^{s_i} d_i\) with \(D, d_i\) odd. By the Chinese Remainder Theorem, \(b^{2^r D} \equiv -1 \pmod n\) holds if and only if \(b^{2^r D} \equiv -1 \pmod{p_i}\) simultaneously for every prime factor \(p_i\). If two factors have different 2-adic valuations \(s_1 \neq s_2\), repeated squaring reaches \(+1 \pmod{p_1}\) while still at \(-1 \pmod{p_2}\), producing a non-trivial square root of unity modulo \(n\).

Arnault's method resolves this in the \(h = 3\) case (\(n = p_1 p_2 p_3\)) by choosing odd multipliers \(k_1 = 1 < k_2 < k_3\) and setting:

$$p_i = k_i(p_1 - 1) + 1 \quad (i = 1, 2, 3), \qquad \left(\frac{b}{p_i}\right) = -1 \quad \forall b \in T.$$

Because \(k_2, k_3\) are odd, every \(p_i - 1\) is divisible by the exact same power of \(2\), so \(s_1 = s_2 = s_3 = s\). And because every \(b \in T\) is a quadratic non-residue modulo each \(p_i\), Euler's criterion gives \(b^{(p_i-1)/2} = b^{2^{s-1} d_i} \equiv -1 \pmod{p_i}\), forcing \(b^{2^{s-1} D} \equiv -1 \pmod n\) across all three primes at once!

Next, as suggested in Prime and Prejudice[2], we choose two small primes \(k_2, k_3 \notin T\) such that the shifted intersection \(R_b\) in \(\mathbb{Z}/4b\mathbb{Z}\) is non-empty for every \(b \in T\):

$$R_b := S_b \;\cap\; k_2^{-1}(S_b + k_2 - 1) \;\cap\; k_3^{-1}(S_b + k_3 - 1) \neq \emptyset \quad \forall b \in T.$$

Finally, Korselt's divisibility condition \((p_i - 1) \mid (p_1 p_2 p_3 - 1)\) reduces to two additional congruences on \(p_1\) modulo \(k_2\) and \(k_3\):

$$p_1 \equiv -k_3^{-1} \pmod{k_2} \qquad \text{and} \qquad p_1 \equiv -k_2^{-1} \pmod{k_3}.$$

Eliminating CRT backtracking via Modulo-4 alignment

Both the Prime and Prejudice article[2] and other implementations known to the author perform multiple CRTs and “backtracking” to find a compatible common solution across \(R_b \subset \mathbb{Z}/4b\mathbb{Z}\), but a much easier approach is possible. Note that all of the moduli \(4b\) are pairwise coprime except for the factor \(4\) multiplying all of them. That means the residue modulo \(4\) is the only obstruction to finding a common solution: it suffices to select one element from each \(R_b\) such that they are all congruent to \(1 \pmod 4\) or all congruent to \(3 \pmod 4\). No CRTs are needed during this search.

def find_congruent(B, prefer_mod4=(3, 1)):
    for r in prefer_mod4:
        solution = []
        for L in B.values():
            found = next((x for x in L if x % 4 == r), None)
            if found is None:
                break
            solution.append(found)
        if len(solution) == len(B):
            return solution
    return None

03 · Finding the Three Primes: The SieveEliminating three residue progressions per prime

Finding a prime \(p_1 \equiv r \pmod M\) such that \(p_2 = k_2(p_1 - 1) + 1\) and \(p_3 = k_3(p_1 - 1) + 1\) are also prime is by far the most expensive part of our algorithm, both in terms of time and memory. Naively trying \(p_1 = r + jM\) for each \(j \in \mathbb{N}\) wastes almost all of its time running big-integer primality tests on candidates that are divisible by small primes just above \(t\).

Let \(S\) be a set of small primes such that \(S \cap (T \cup \{k_2, k_3\}) = \emptyset\), and set \(A_i := k_i(r - 1) + 1\) for \(i = 2, 3\), so that \(p_i = A_i + k_i M j\). Then for any sieve prime \(q \in S\), divisibility of \(p_1, p_2, p_3\) by \(q\) translates into three linear congruences on the index \(j\):

$$\begin{aligned} q \mid p_1 &\iff j \equiv -rM^{-1} \pmod q, \\ q \mid p_2 &\iff j \equiv -A_2(k_2 M)^{-1} \pmod q, \\ q \mid p_3 &\iff j \equiv -A_3(k_3 M)^{-1} \pmod q. \end{aligned}$$

We can save redundant modular reductions by setting \(b_1 := -rM^{-1} \pmod q\) and \(d_i := (1 - k_i^{-1})M^{-1} \pmod q\):

$$b_1 = -rM^{-1} \pmod q, \qquad b_2 = b_1 + d_2 \pmod q, \qquad b_3 = b_1 + d_3 \pmod q.$$

Thus for each interval of length \(q\), we eliminate up to three indices \(b_1, b_2, b_3 \pmod q\). By making the sieve segmented in blocks of length \(L\), we quadratically reduce memory complexity while scanning surviving 1-bytes at C speed via good.find(1, i + 1).

Why Pritchard's wheel sieve does not consistently beat the segmented sieve. Because all primes \(p \le t\) are already factors of \(M\), our sieve begins at the first prime \(q > t\) (e.g. \(q = 1201\)), where each prime eliminates three residue classes. Building a dynamic wheel over primes \(q > t\) requires tracking \(3^k\) irregular gaps across huge periods \(\prod q_i\), losing the contiguous stride that makes good[i::q] = zero_buf[:n] fast and causing performance to fluctuate randomly with \(t\).
SageMath · Segmented bytearray sieve with pre-allocated zero bufferclick to expand 
def prepare_sieve(M, r, k2, k3, t, B):
    data = []
    for q in prime_range(t + 1, B + 1):
        if q == k2 or q == k3:
            continue
        invM = inverse_mod(M, q)
        invk2 = inverse_mod(k2, q)
        invk3 = inverse_mod(k3, q)

        b1 = (-r * invM) % q
        b2 = (b1 + (1 - invk2) * invM) % q
        b3 = (b1 + (1 - invk3) * invM) % q

        data.append((q, tuple({b1, b2, b3})))
    return data

def sieve_block(k0, L, data, zero_buf):
    good = bytearray(b'\x01') * L
    for q, residues in data:
        for b in residues:
            i = (b - k0) % q
            if i < L:
                n = (L - 1 - i) // q + 1
                good[i::q] = zero_buf[:n]
    return good

04 · Primality TestingQuadratic reciprocity, Mod-8 selection & the Strong Lucas test

Once a candidate index \(j\) survives the sieve, we test \(p_1, p_2, p_3\) for probable primality. Sage's built-in is_pseudoprime() calls PARI/GP's Baillie–PSW test[3], which consists of three steps: trial division by primes \(< 101\) (redundant after our sieve), a base-2 Miller–Rabin test, and an almost-extra-strong Lucas test.

We can make the base-2 Miller–Rabin step significantly faster by combining Euler's criterion with the second supplement to Quadratic Reciprocity. For any odd prime \(p = 2^s d + 1\) (\(d\) odd), the Legendre symbol \(\left(\frac{2}{p}\right)\) fixes the sign of \(2^{(p-1)/2} = 2^{2^{s-1} d} \pmod p\) according to \(p \bmod 8\):

$$2^{2^{s-1}d} \equiv \left(\frac{2}{p}\right) = (-1)^{(p^2-1)/8} \equiv \begin{cases} +1 \pmod p & \text{if } p \equiv 1, 7 \pmod 8, \\ -1 \pmod p & \text{if } p \equiv 3, 5 \pmod 8. \end{cases}$$

This yields four specialized cases depending on \(p \bmod 8\), which is already fixed before the sieve loop begins:

$$\begin{aligned} p \equiv 1 \pmod 8 &\implies s \ge 3, \quad 2^d \equiv 1 \pmod p \;\text{ or }\; 2^{2^r d} \equiv -1 \pmod p \;\;\text{for some } 0 \le r \le s-2, \\ p \equiv 3 \pmod 8 &\implies s = 1, \quad 2^d = 2^{(p-1)/2} \equiv -1 \pmod p, \\ p \equiv 5 \pmod 8 &\implies s = 2, \quad 2^{2d} = 2^{(p-1)/2} \equiv -1 \pmod p, \\ p \equiv 7 \pmod 8 &\implies s = 1, \quad 2^d = 2^{(p-1)/2} \equiv +1 \pmod p. \end{aligned}$$

Therefore, the “full” Miller–Rabin squaring loop is only needed when \(p \equiv 1 \pmod 8\) (and only up to \(r = s - 2\)). In the other three cases, \(s\) is known in advance (\(s = 1\) for \(3, 7 \pmod 8\) and \(s = 2\) for \(5 \pmod 8\)), so only a single congruence needs to be checked without even calling d.valuation(2)!

Selecting \(k_2, k_3\) so that \(p_i \not\equiv 1 \pmod 8\)

Notice that because \(2 \in T\), the first set of non-quadratic residues is \(S_2 = \{3, 5\} \pmod 8\), which means \(r \bmod 8 = \texttt{candidate\_sol[0]} \in \{3, 5\}\) automatically! Even better, by partitioning our supplemental primes so that \(k_2 \equiv k_3 \equiv 1 \pmod 4\) are tried first and checking \(r \equiv 3 \pmod 4\) before \(1 \pmod 4\), we ensure \(p_1 \equiv p_2 \equiv p_3 \equiv 3 \pmod 8\), where every candidate test is a single modular exponentiation pow(2, (p - 1) >> 1, p) == p - 1.

def MR_3(p):
    # p == 3 mod 8 => s = 1 always, d = (p - 1) >> 1, and (2/p) = -1
    return pow(2, (p - 1) >> 1, p) == p - 1

def MR_5(p):
    # p == 5 mod 8 => s = 2 always, d = (p - 1) >> 2, and (2/p) = -1
    d = (p - 1) >> 2
    x = pow(2, d, p)
    return (x * x) % p == p - 1

def MR_7(p):
    return pow(2, (p - 1) >> 1, p) == 1

def MR_1_checked(p):
    d = p - 1
    s = d.valuation(2)
    d >>= s
    x = pow(2, d, p)
    if x == 1 or x == p - 1:
        return not p.is_square()
    for _ in range(s - 3):
        x = (x * x) % p
        if x == p - 1:
            return not p.is_square()
    return False

The Strong Lucas test — and why omitting it in the hot loop is faster

In the Baillie–PSW test, base-2 Miller–Rabin is paired with a Strong Lucas probable prime test. Using Selfridge's method, we pick the first discriminant \(D \in \{5, -7, 9, -11, 13, \dots\}\) for which the Jacobi symbol \(\left(\frac{D}{n}\right) = -1\), and set \(P = 1, Q = (1 - D)/4\) (or \(P = Q = 5\) if \(D = 5\)). The companion Lucas sequences \(U_k, V_k\) are defined by \(U_0 = 0, U_1 = 1, V_0 = 2, V_1 = P\) and:

$$U_{j+2} = P U_{j+1} - Q U_j, \qquad V_{j+2} = P V_{j+1} - Q V_j.$$

Writing \(n + 1 = 2^{s'} d'\) with \(d'\) odd, the Strong Lucas test accepts \(n\) if and only if:

$$U_{d'} \equiv 0 \pmod n \quad \text{or} \quad V_{2^r d'} \equiv 0 \pmod n \quad \text{for some } 0 \le r < s'.$$

While Miller–Rabin operates in \(\mathbb{F}_p^\times\) of order \(p - 1\), the Lucas test operates in the norm-1 subgroup of \(\mathbb{F}_{p^2}^\times\) of order \(p + 1\), making the two tests algebraically orthogonal. However, advancing the binary Lucas state \((U_k, V_k, Q^k) \bmod n\) is roughly \(3\times\) more expensive than a base-2 Miller–Rabin test, and high confidence of primality inside the sieve loop is unnecessary because we test the final product \(n = p_1 p_2 p_3\) against all bases in \(T\) at the end anyway. Ignoring the Lucas test in the inner loop yields a substantially faster program.

SELFRIDGE_D = tuple((-1) ** i * (2 * i + 5) for i in range(20))

def lucas_uv(n, k, P, Q):
    D = P * P - 4 * Q
    inv2 = inverse_mod(2, n)
    U, V, Qk = Integer(1), P % n, Q % n
    for bit in bin(k)[3:]:
        U2 = (U * V) % n
        V2 = (V * V - 2 * Qk) % n
        Q2 = (Qk * Qk) % n
        if bit == '0':
            U, V, Qk = U2, V2, Q2
        else:
            U = ((P * U2 + V2) * inv2) % n
            V = ((D * U2 + P * V2) * inv2) % n
            Qk = (Q2 * Q) % n
    return U, V, Qk

05 · Asymptotic HeuristicsChebyshev's function, Mertens' theorem & optimal sieving

To find the optimal parameters for the sieve, let us estimate the size of \(M\) and of our final pseudoprime with respect to the input bound \(t\). By definition:

$$M = 4 \cdot k_2 \cdot k_3 \cdot \prod_{p \le t} p.$$

Taking natural logarithms gives:

$$\ln(M) = \vartheta(t) + \ln(4) + \ln(k_2) + \ln(k_3), \qquad \text{where } \vartheta(t) := \sum_{p \le t} \ln(p)$$

is Chebyshev's first function. Using the Prime Number Theorem asymptotic \(\vartheta(t) \sim t\), we obtain \(M \sim e^{(1+o(1))t}\), so the number of decimal digits of \(M\) is roughly \(\log_{10}(e) \cdot t \approx 0.434\,t\). A single Miller–Rabin test on a number with \(\Theta(t)\) digits has time complexity \(\tilde{O}(t^2)\) using FFT-based multiplication.

Now consider the cost of sieving over all primes \(t < q \le B\). Since each prime \(q\) eliminates \(3\) residue classes out of \(q\), the fraction of surviving candidates after the sieve is given by:

$$s(t, B) := \prod_{t < q \le B} \left(1 - \frac{3}{q}\right).$$

For each prime \(q > 3\), expanding the cube shows that:

$$0 < \left(1 - \frac{3}{q}\right) < \left(1 - \frac{1}{q}\right)^3, \qquad \text{since } \left(1 - \frac{1}{q}\right)^3 - \left(1 - \frac{3}{q}\right) = \frac{3}{q^2} - \frac{1}{q^3} > 0.$$

Taking products and applying Mertens' third theorem:

$$0 \le \lim_{n \to \infty} \ln(n)^3 \prod_{q \le n} \left(1 - \frac{3}{q}\right) \le \lim_{n \to \infty} \ln(n)^3 \prod_{q \le n} \left(1 - \frac{1}{q}\right)^3 = e^{-3\gamma},$$

which implies \(\prod_{q \le n} (1 - 3/q) \sim c_0 \ln(n)^{-3}\), and therefore:

$$s(t, B) = \frac{\prod_{q \le B} \left(1 - \frac{3}{q}\right)}{\prod_{q \le t} \left(1 - \frac{3}{q}\right)} \sim \left(\frac{\ln(t)}{\ln(B)}\right)^3.$$

Setting \(B = t^a\) (or \(B = c \cdot t^a\) with constant multiplier \(c > 0\)), the survivor fraction is \(s(t, t^a) \sim 1/a^3\). Sieving up to \(B = t^a\) takes \(\tilde{O}(t^a)\) time, whereas testing the surviving candidates takes \(\tilde{O}(t^2 / a^3)\) time. Minimizing total runtime requires balancing these two costs:

$$t^a \approx \frac{t^2}{a^3} \quad \implies \quad a \approx 2 - \frac{3\ln a}{\ln t} \lesssim 2.$$

Since \(a\) is much smaller than \(t\), the optimal exponent is \(a \approx 2\), so we sieve over primes up to roughly \(B \approx c \cdot t^2\).

Theory vs. Practice: Why the bare equation gives a < 2, yet experiments favor B ≈ 10 t²

A closer look at the total work function reveals an instructive subtlety between pure \(\tilde{O}(\cdot)\) asymptotics and empirical runtime:

  • Marginal return of the bare asymptotic sum: If we strip away constant and logarithmic factors and minimize the bare sum \(W_{\text{bare}}(a) = t^a + t^2 / a^3\) by setting \(\frac{dW}{da} = 0\), we obtain \((\ln t)\, t^a = \frac{3}{a} \cdot \frac{t^2}{a^3}\), or \(t^{a-2} = \frac{3}{a^4 \ln t} \ll 1\). Because sieve cost grows exponentially in \(a\) (with derivative factor \(\ln t\)) whereas the Mertens survivor fraction \(1/a^3\) decays only polynomially (with derivative factor \(3/a\)), unit constants place the minimum strictly below \(a = 2\) (where sieve work is roughly \(\frac{3}{a \ln t} \approx \frac{1}{5}\) of the primality test work).
  • Why real SageMath runs peak around \(a = 2, c \approx 10\) (\(B \approx 10\,t^2\)): In practice, \(\tilde{O}(\cdot)\) hides a large constant-factor asymmetry \(K = C_{\text{MR}} / C_{\text{sieve}} \gg 1\). First, the sieve only iterates over primes \(q \le B\), of which there are \(\pi(B) \sim \frac{B}{a \ln t}\), and each inner sieve step is a fast C bytearray slice assignment (memcpy). Second, every surviving candidate must execute multi-precision modular exponentiation pow(2, (p1 - 1) >> 1, p1) on a \(\Theta(t)\)-bit integer (\(\sim 1{,}730\) squarings at \(t = 1200\)) across all candidates searched until \(p_1, p_2, p_3\) are simultaneously prime.

Including prime density \(\pi(B) \sim \frac{B}{\ln B}\) and the empirical per-survivor cost ratio \(K \approx 100\), the derivative condition \(\frac{dW}{dB} = 0\) for \(B = c \cdot t^a = t^\alpha\) (where \(\alpha = a + \frac{\ln c}{\ln t}\)) yields:

$$W(B) \propto \frac{c \cdot t^a}{\alpha} + \frac{K \cdot t^2}{\alpha^3} \quad \implies \quad B_{\text{opt}} \approx \frac{3K}{\alpha^2(\alpha \ln t - 1)} \, t^2.$$

For practical sizes \(t \in [256, 10000]\), the prefactor \(\frac{3K}{\alpha^2(\alpha \ln t - 1)}\) evaluates to roughly \(5 \text{ to } 10\), explaining why \(B \approx 10\,t^2\) (\(a = 2, c \approx 10\), or \(a \approx 2.2\) when \(c = 1\)) is optimal in actual runs, while as \(t \to \infty\) the \(\ln t\) denominator eventually dominates and pulls \(\alpha_{\text{opt}} \to 2^-\).

06 · Final RemarksPorting to C, PARI/GP, GMP & multithreading

While our algorithmic optimizations bring the SageMath program down to a few seconds, Python remains slower than C for tight inner loops. Porting the search to C using PARI/GP[3] or GNU MP (GMP) unlocks two further optimizations:

  • Native C / GMP limb arithmetic: Different implementations of Baillie–PSW use slightly different variants of the Lucas test (see PARI/GP's basemath/prime.c[3]). Even better, GMP's low-level mpz_powm_ui and mpn_ functions operate on pre-allocated limb buffers without heap allocation, and base-2 modular exponentiation replaces general multi-precision multiplications with 1-bit shifts.
  • Multithreaded segmented sieving: Because each segmented block \([k_0, k_0 + L)\) only reads from the shared precomputed sieve table data, worker threads in C (via OpenMP or pthreads) can sieve and test disjoint blocks in parallel with near-linear speedup.
